# 实时流虚拟歌单：后端需求

> 播放器已实现「点即播 + 动态续拉」。本文档描述后端需要配合的约定。

## 背景

播放器把推荐分组卡片区分为两类：

- 静态虚拟歌单：每次 getPlaylist 返回同样内容（榜单、分类、猜你喜欢、每日30首）。播放器显示为列表页。
- 实时流虚拟歌单：每次 getPlaylist 返回最新一批、内容会变。播放器点卡片即播，并在队列快播完时自动续拉。

目前已实现为实时流的只有「每日推荐」（virtual:daily）。

---

## 播放器如何识别实时流

播放器用白名单精确匹配 playlistId：

- 每日推荐：virtual:daily

只有这个 id 会走「点即播 + 动态续拉 + 封面播放按钮」。
其余虚拟歌单（virtual:daily30、virtual:toplist:*、virtual:guess、
virtual:category:* 等）保持静态列表，不会显示封面播放按钮。

如果将来新增实时流歌单，播放器在 STREAM_PLAYLIST_IDS 白名单里追加即可。

---

## 后端接口要求

### 1. getRecommendations 返回分组

type=daily 的 sections 中，每日推荐作为一项返回，kind=playlist，playlistId=virtual:daily。

每项字段：

- id：分组标识
- title：标题
- kind：playlist
- playlistId：虚拟歌单 id
- coverArt：可选封面

示例：id=daily, title=每日推荐, kind=playlist, playlistId=virtual:daily

### 2. getPlaylist 支持实时流 + exclude

    GET /rest/getPlaylist.view?id=<playlistId>&exclude=<已播id逗号分隔>

要求：

- id=virtual:daily 时，返回当前推荐的一批歌（约 10 首），每次调用内容可以不同。
- exclude（可选）：逗号分隔的已播放歌曲 id，服务端应过滤掉这些 id，返回新的歌。
- 返回标准 playlist.entry[]，每首含：id / title / artist / album / duration / coverArt / suffix / qualityLevels。
- 若过滤后不足一批，服务端应尽量补足（从推荐池里找未在 exclude 中的）。

### 3. exclude 长度约束

播放器会裁剪到最近 500 个已播 id（约 6~7 KB URL）。服务端应能接受这个量级；若你的网关 URL 限制更小，请告知，播放器可下调上限。

---

## 播放器行为（供参考）

1. 用户点每日推荐卡片（或封面上的播放按钮）→ 拉一批 → 从第一首开始播。
2. 队列剩余 ≤ 2 首时（自动播完或手动切歌都算）→ 请求 getPlaylist?id=...&exclude=<已播id>。
3. 新歌追加到队列末尾；已播 id 累积（上限 500）。
4. 续拉返回空/失败 → 停止续拉，队列播完结束。
5. 用户切到普通歌单 → 停止续拉。

## 验收清单

- [ ] getRecommendations(type=daily) 的 sections 中，每日推荐 playlistId = virtual:daily
- [ ] getPlaylist?id=virtual:daily 返回一批（约 10 首）标准 entry
- [ ] getPlaylist?id=virtual:daily&exclude=<ids> 过滤掉已播 id
- [ ] 连续两次带不同 exclude 调用，返回内容不重复
- [ ] URL 长度在 500 个 id 时仍可正常响应
